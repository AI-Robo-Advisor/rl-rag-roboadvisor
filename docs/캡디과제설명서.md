### #1. 미션 소개

로보어드바이저(Robo-Advisor)는 알고리즘 기반으로 투자자의 성향을 분석하고 최적의 포트폴리오를 추천하는 자동화된 자산관리 서비스다. 국내외 자산운용사, 핀테크 기업, 증권사에서 개인 맞춤형 자산관리 서비스로 활용된다.
이 미션에서는 강화학습 기반 동적 자산배분 엔진과 LLM 기반 에이전틱 투자 리서치 시스템을 결합한 '통합 자율 로보어드바이저'를 구축한다. 단순 수익률 극대화가 아닌, "왜 이 자산을 매수했는가?"에 대한 논리적 근거(Reasoning Trace)를 제시하는 설명 가능한 AI 시스템을 설계한다.

강화학습 엔진과 에이전틱 리서치는 독립적으로 동작하는 것이 아니라, 리서치 에이전트가 탐지한 위험 이벤트(규제 변경, 실적 쇼크, 지정학 리스크 등)를 '리스크 태그'로 변환하여 강화학습 환경의 관측 공간에 반영하고, Safe-Guard 모니터링에 연동하는 통합 파이프라인으로 설계한다. 이를 통해 "뉴스에서 발견된 리스크가 포트폴리오 비중 조정에 어떻게 반영되는가"를 end-to-end로 추적할 수 있다.
학습자는 금융 시계열의 비정상성(Non-stationarity) 처리, 보상 함수 설계가 리스크 관리에 미치는 영향, SHAP 기반 의사결정 해석, ANOVA 통계 검증을 직접 구현하며 이해한다. 이 경험은 금융 AI 규제(XAI 의무화) 대응 역량과 현업 수준의 아키텍처 사고력을 확보하는 기반이 된다.

이 미션의 평가는 '수익률 숫자 달성'보다 '검증 가능한 과정'에 더 큰 가중치를 둔다. 즉, Why(왜 이 보상 함수를 선택했는가), How(어떤 통계적 방법으로 검증했는가), When(어떤 시장 조건에서 전략이 유효한가)을 체계적으로 문서화하고 설명할 수 있는 역량이 핵심 목표다.

### #3. 과제 목표

이 과제를 마친 후, 학습자는 아래를 스스로 설명할 수 있어야 한다.

- 금융 시계열의 비정상성(Non-stationarity)을 해결하기 위한 전처리 기법을 설명할 수 있다.
- 강화학습의 보상 함수(Reward Function) 설계가 포트폴리오 리스크 관리에 미치는 영향을 이해한다.
- 에이전틱 RAG 아키텍처에서 'Self-Correction' 루프가 환각(Hallucination) 억제에 필요한 이유를 설명할 수 있다.
- SHAP 값을 활용한 모델 의사결정 해석 방법과 금융 규제(XAI 의무화) 대응 방안을 이해한다.
- ANOVA 검증을 통해 투자 전략 간 성과 차이의 통계적 유의성을 검증하는 방법을 설명할 수 있다.
- 정적 최적화(MVO)와 동적 최적화(DRL)의 차이점과 각각의 장단점을 구분할 수 있다.
- 리서치 에이전트의 위험 이벤트 탐지 결과가 강화학습 포트폴리오 비중 조정에 반영되는 end-to-end 파이프라인을 설명할 수 있다.

### #5. 기능 요구 사항

다음 요구사항을 모두 만족해야 한다. 

1. 데이터 수집 및 전처리
    - yfinance 또는 pykrx를 통해 10개 이상 자산의 5년 이상 수정주가 데이터를 자동 수집해야 한다.
    - 수익률 계산 시 로그 수익률(Log Return)을 사용해야 한다.
    - 결측치는 Forward Fill 후 남은 결측치는 제거해야 한다.
    - 정규화(Z-score 또는 Min-Max) 전처리를 적용해야 한다.
2. 강화학습 환경 (Gymnasium)
    - OpenAI Gymnasium 인터페이스를 준수하여 거래 환경을 구현해야 한다.
    - 거래 수수료(0.015%)와 슬리피지(0.05%)를 환경에 반영해야 한다.
    - 관측 공간(Observation Space)에 최소 다음 정보를 포함해야 한다: 과거 N일 수익률, 현재 포트폴리오 비중, 기술적 지표(RSI, MACD 등) 2개 이상.
    - 설계 가이드
        - 관측 윈도우 N은 20~60 거래일을 권장한다. N이 작으면(20일) 단기 모멘텀에 민감하고 차원이 낮아 학습이 빠르지만 추세 파악이 약하며, N이 크면(60일) 중장기 추세를 반영하지만 차원 증가로 학습 속도가 느려진다. 선택 근거를 리포트에 기술해야 한다.
    - 행동 공간(Action Space)은 연속적 비중 조절(Continuous) 또는 이산적 리밸런싱(Discrete) 중 선택하여 구현해야 한다.
3. 보상 함수 설계
    - 보상 함수는 수익률 극대화와 리스크(변동성 또는 MDD) 억제를 가중 결합해야 한다.
    - 최소 3가지 보상 함수 변형을 실험하고 비교 결과를 문서화해야 한다:
        - 변형 1 : 단순 수익률 기반 (reward = r_t)
        - 변형 2 : 샤프비율 기반 (reward = r_t / sigma_t)
        - 변형 3 : 수익률 + MDD 페널티 결합 (reward = r_t - lambda * MDD_t)
        - 변형 3에서 lambda(MDD 페널티 강도) 권장 탐색 범위는 0.5~5.0이다. lambda=1.0을 기본값으로 시작하여, lambda 변화에 따른 수익률-MDD 트레이드오프 곡선을 실험하고 선택 근거를 문서화한다. 예: lambda=0.5이면 공격적(수익률 우선), lambda=5.0이면 방어적(MDD 억제 우선).
    - MDD 15% 초과 시 에피소드를 조기 종료하는 Safe-Guard 로직을 포함해야 한다.
4. 강화학습 모델 학습
    - PPO(Proximal Policy Optimization) 알고리즘을 적용해야 한다.
    - Stable-Baselines3 또는 직접 구현 중 선택할 수 있다.
    - 학습 곡선(Episode Reward)을 시각화하여 수렴 여부를 확인해야 한다.
    - 최소 100,000 스텝 이상 학습해야 한다.
5. 백테스트 및 성과 평가
    - Walk-Forward Validation 방식(학습 4년 → 테스트 1년)으로 백테스트를 수행해야 한다.
        - Walk-Forward 시나리오 예시: Window 1 = 학습 2019~2022 / 테스트 2023, Window 2 = 학습 2020~2023 / 테스트 2024. 최소 2개 윈도우를 사용하여 시간 축 이동에 따른 성과 안정성을 검증한다. 윈도우 이동 시 모델을 완전히 재학습(Re-training)해야 한다.
    - 다음 12개 지표를 계산하여 리포트에 포함해야 한다:
        - 수익률 : 누적 수익률, CAGR
        - 리스크 : 연환산 변동성, VaR(95%), CVaR(95%), MDD
        - 위험조정 : 샤프비율, 소르티노비율, Calmar Ratio
        - 상대성과 : Alpha, Beta, Information Ratio
    - 벤치마크(KOSPI 또는 S&P500)와 동일가중 포트폴리오 대비 성과를 비교해야 한다.
6. MVO(정적 최적화) 비교 기준 구현 명세
    - DRL과의 공정한 비교를 위해 MVO(Mean-Variance Optimization) 기준 포트폴리오는 다음 최소 요건을 충족해야 한다
        - 평균-분산 최적화(Markowitz) 기반으로 구현한다.
        - 공분산 행렬은 과거 252 거래일(약 1년) 롤링 윈도우로 추정한다.
        - 제약조건: 각 자산 비중 합 = 1, 공매도 금지(비중 >= 0), 개별 자산 최대 비중 <= 40%.
        - 목적함수: 최대 샤프비율 또는 최소 분산 포트폴리오 중 선택하고, 선택 근거를 문서화한다.
        - 리밸런싱 주기: 월 1회(매월 첫 거래일) 또는 분기 1회를 적용한다.
        - scipy.optimize.minimize를 사용하여 구현하며, 최적화 수렴 여부를 확인한다.
7. SHAP 기반 의사결정 해석
    - 강화학습 모델의 행동 결정에 대해 SHAP 값을 계산해야 한다.
    - 특정 시점의 포트폴리오 비중 결정에 어떤 피처가 영향을 미쳤는지 시각화해야 한다.
    - Summary Plot과 Force Plot을 최소 각 1개 이상 생성해야 한다.
    - SHAP 해석 결과를 대시보드에서 조회할 수 있어야 한다.
8. ANOVA 통계 검증
    - 다음 3가지 ANOVA 검증을 수행해야 한다:
        - 검증 1 : 보상 함수 변형별(3가지) 성과 비교 (One-way ANOVA)
        - 검증 2 : DRL 전략 vs MVO 전략 vs 동일가중 전략 비교 (One-way ANOVA)
        - 검증 3 : 시장 국면별(상승/횡보/하락) 전략 성과 비교 (Two-way ANOVA)
    - 각 검증의 F-통계량, p-value, 효과 크기(η²)를 리포트에 포함해야 한다.
    - p < 0.05인 경우 사후 검정(Tukey HSD)을 수행해야 한다.
9. 에이전틱 투자 리서치 (LangGraph + RAG)
    - LangGraph를 활용하여 계획-수행-검증의 다단계 에이전트 워크플로우를 구현해야 한다.
    - 금융 뉴스 데이터를 ChromaDB(또는 Pinecone)에 벡터화하여 저장해야 한다.
    - 검색 결과가 부적절하다고 판단될 경우 쿼리를 수정하여 재검색하는 Self-Correction 로직을 포함해야 한다.
    - 모든 리서치 결과에는 원문 출처(Source Citation)를 반드시 명시해야 한다.
    - 에이전트의 "현재 생각"을 로그 형식으로 대시보드에 노출해야 한다.
    - 리서치 에이전트가 탐지한 위험 이벤트(실적 쇼크, 규제 변경, 급등락 등)를 리스크 태그로 변환하여 강화학습 환경의 관측 공간 또는 리스크 모니터링 모듈에 반영하는 연동 인터페이스를 구현해야 한다.
10. API 서빙 (FastAPI)
    - 다음 5개 엔드포인트를 구현해야 한다:
        - `GET /health` : 서버 상태 및 모델 로드 여부 반환
        - `POST /optimize` : 현재 시장 데이터 기반 최적 포트폴리오 비중 반환
        - `POST /explain` : 특정 의사결정에 대한 SHAP 해석 반환
        - `POST /research` : 투자 질문에 대한 에이전틱 리서치 결과 반환
        - `GET /backtest` : 백테스트 성과 지표 반환
    - Pydantic 스키마를 정의하고 Swagger UI를 자동 생성해야 한다.
    - 추론 시간은 요청 1건당 5초 이내여야 한다.
11. 대시보드 (Streamlit)
    - 대시보드는 모델을 직접 로드하지 않고, 반드시 FastAPI 서버와 HTTP 통신해야 한다.
    - 다음 6개 페이지/탭을 구현해야 한다:
        - 포트폴리오 현황: 현재 자산 비중, 누적 수익률 차트
        - 강화학습 성과: 학습 곡선, 백테스트 결과, 벤치마크 비교
        - SHAP 해석: 의사결정 설명 시각화
        - 에이전트 리서치: 질문 입력 → 추론 과정 → 결과 출력
        - ANOVA 검증 결과: 통계 검증 요약 테이블 및 시각화
        - 리스크 모니터링: VaR/CVaR 게이지, MDD 추이, Safe-Guard 알림
12. 개발 환경 및 산출물

### #7. 제약 사항

- 개발 환경
    - Python 3.10 이상을 사용해야 한다.
    - 강화학습 : Stable-Baselines3 또는 PyTorch 직접 구현
    - LLM : LangChain, LangGraph 사용 (OpenAI API 또는 로컬 모델)
    - 벡터DB : ChromaDB 또는 Pinecone
    - Docker를 사용하여 실행 환경을 구성해야 한다.
    - 라이브러리 버전 관리 :
        - requirements.txt에 주요 라이브러리의 고정 버전을 명시해야 한다.
        - 특히 stable-baselines3, shap, langchain, langchain-core, langgraph, chromadb, fastapi, streamlit은 호환성 이슈가 빈번하므로 버전 고정(pinning)을 권장한다.
        - 예: stable-baselines3==2.3.0, shap==0.45.0, langchain>=0.2.0,<0.3.0
- 데이터
    - 실제 금융 데이터는 yfinance, pykrx 등 공개 API를 통해 수집해야 한다.
    - 테스트 데이터의 라벨(미래 수익률)을 학습에 사용하는 것을 금지한다.
    - 시계열 데이터는 반드시 시간 순서를 유지해야 한다 (미래 정보 누수 금지).
    - 금융 뉴스 크롤링 시 다음 규칙을 준수해야 한다.
        - 허용 소스: 네이버 금융 뉴스(RSS), 한국경제 오픈 API, 금융감독원 DART 공시 등 공개 데이터 우선 활용
        - 요청 빈도: robots.txt 준수, 초당 1회 이하 요청, 과도한 크롤링 금지
        - 저장 포맷: 제목, 본문 요약(300자 이내), 게시일, 원문 URL을 구조화하여 저장
        - 원문 링크 보존: 벡터 DB 메타데이터에 원문 URL을 반드시 포함하여 출처 추적 가능하게 유지
        - 면책: 수집한 뉴스 데이터는 교육 목적으로만 사용하며, 재배포를 금지한다
- 아키텍처
    - 프론트엔드(Streamlit) 코드에서 모델 파일을 직접 로드하는 것을 금지한다.
    - 반드시 API 통신을 통해서만 추론 결과를 받아야 한다 (MSA 구조 강제).
    - API Key는 .env 파일로 관리하며 GitHub 업로드를 금지한다.
- 코드 품질
    - GitHub의 Issue와 Pull Request 기능을 활용하여 개발 이력을 남겨야 한다.

### #8. 보너스 과제 (선택)

1. 보너스 1 – 이상거래 탐지 시스템
    - 해야 할 작업 : Isolation Forest 또는 Autoencoder를 활용하여 포트폴리오 내 비정상적인 가격 변동(급등락, 거래량 이상)을 탐지하는 모듈을 추가한다. 이상 탐지 시 대시보드에 알림을 표시하고, 해당 자산의 비중을 자동으로 축소하는 Safe-Guard 로직과 연동한다.
    - 배움 포인트 : 비지도 학습 기반 이상 탐지 기법의 금융 적용 방법과 리스크 관리 자동화를 경험한다.
2. 보너스 2 – 멀티모달 시장 분석
    - 해야 할 작업 : 텍스트 뉴스뿐만 아니라 주가 차트 이미지를 분석하여 패턴(Head and Shoulders, Double Top 등)을 인식하는 Vision 모델을 에이전트 도구로 추가한다.
    - 배움 포인트 : 텍스트와 이미지 데이터를 결합한 멀티모달 의사결정 역량을 확보한다.
3. 보너스 3 – MLOps 파이프라인 구축
    - 해야 할 작업 : MLflow를 활용하여 모델 버전 관리 및 실험 추적을 구현한다. 일일 데이터 수집 및 모델 재학습 파이프라인을 자동화(Airflow 또는 Cron)한다.
    - 배움 포인트 : 프로덕션 환경의 ML 시스템 운영 방법을 경험한다.
4. 보너스 4 – 공정성(Fairness) 분석
    - 해야 할 작업 : 강화학습 모델이 특정 섹터나 시가총액 규모에 편향되어 있는지 분석한다. 섹터별 수익률 분포, 대형주/중소형주 비중 변화를 추적하고, 편향이 발견되면 완화 방법을 적용한다.
    - 배움 포인트 : 금융 AI의 공정성 이슈와 편향 완화 기법을 경험한다.

### 추천 데이터셋 및 획득 방법

1. 필수 활용 데이터 (직접 수집)
    
    
    | 데이터 | 설명 | 수집 방법 | 활용 |
    | --- | --- | --- | --- |
    | 국내 주식/ETF 가격 | KODEX 200, TIGER 미국S&P500 등 | pykrx `stock.get_etf_ohlcv_by_date()` | 포트폴리오 최적화 |
    | 해외 주식/ETF 가격 | SPY, QQQ, TLT, GLD 등 | FinanceDataReader 또는 yfinance `download()` | 글로벌 자산배분 |
    | KOSPI/S&P500 지수 | 벤치마크 | pykrx `stock.get_index_ohlcv_by_date()` | 백테스트 비교 |
    | ETF 시가총액 | Black-Litterman Prior | pykrx `stock.get_etf_portfolio_deposit_file()` | 시장 가중치 |
    | 금융 뉴스 | 에이전틱 RAG 소스 | 네이버 금융, 한경 API 또는 크롤링 | 에이전틱 RAG 소스 |
    - 수집 코드 예시 :
        
        ```python
        # 국내 ETF 데이터 수집 (pykrx)
        from pykrx import stock
        import pandas as pd
        
        tickers = ['069500', '102110', '148020']  # KODEX 200, TIGER 200, KBSTAR 200
        start_date = '20190101'
        end_date = '20241231'
        
        data = {}
        for ticker in tickers:
            df = stock.get_etf_ohlcv_by_date(start_date, end_date, ticker)
            data[ticker] = df['종가']
        
        prices = pd.DataFrame(data)
        returns = np.log(prices / prices.shift(1)).dropna()
        ```
        
        ```python
        # 해외 ETF 데이터 수집 (yfinance)
        import yfinance as yf
        
        tickers = ['SPY', 'QQQ', 'IWM', 'EFA', 'AGG', 'GLD', 'VNQ']
        data = yf.download(tickers, start='2019-01-01', end='2024-12-31')
        prices = data['Adj Close']
        returns = np.log(prices / prices.shift(1)).dropna()
        ```
